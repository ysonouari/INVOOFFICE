## Résumé

**INVOOFFICE** — Application SaaS de facturation 100% client-side pour entrepreneurs marocains.
Crée des devis, factures, bons de livraison et avoirs en PDF conformes DGI.
Stack : JavaScript ES modules, Supabase (auth), html2canvas + jsPDF (PDF), localStorage/IndexedDB/OPFS (stockage), PWA (Service Worker), Vercel (déploiement).

---

## Architecture

| Couche | Technologie | Détail |
|---|---|---|
| **Frontend** | ES modules natifs, sans bundler | `js/` (25 modules), `modules/` (auth, admin, landing) |
| **Auth** | Supabase | RLS, rate limiting client-side + honeypot |
| **Stockage** | localStorage (source) + IndexedDB (miroir) + OPFS (PDF/images) | `fb_company`, `fb_history`, `fb_clients` |
| **PDF** | PDFKit (défaut) + jsPDF (fallback) | Fond entit.png JPEG 0.88 natif + contenu PNG transparent + overlay invisible |
| **PWA** | Service Worker | Cache-first assets, skip cross-origin (CDN loads natively), precache 63 fichiers |
| **i18n** | i18next | FR/AR avec RTL |
| **CSS** | Design tokens (variables) | Dark/light mode, pas de couleur hardcodée |
| **Tests** | Playwright 1.61 | 226 tests / 49 fichiers (tous verts, workers 2, serveur warm), config dans `tests/playwright.config.ts` |

- **Phase PDF stabilisée** — Ne pas modifier le pipeline sans nouvelle étude (cf. `docs/audit/DECISION_VECTOR_TEXT_AR.md`)
- **Pagination** : **1 `.pdf-page` HTML = 1 page A4** (hauteur fixe 297 mm, `overflow:hidden`). Le contenu est paginé **avant** html2canvas (`buildPages()`), chaque page porte son propre fond d'en-tête et son propre footer. html2canvas capture **page par page**, jsPDF reçoit **1 image = 1 page** (`addImage(img, 0, 0, 210, 297)`).
- **Zone de sécurité footer** : `SAFETY_MM = 8` mm réservés avant le footer (via `padding-bottom:8mm` sur `.pdf-content`). Détection de débordement : `scrollHeight > clientHeight` (jamais soustraire la marge dans la comparaison — `scrollHeight` est borné inférieurement par `clientHeight`).
- **Bloc final insécable** : totaux + montant en lettres + conditions + note dans un nœud DOM unique `.pdf-final-block`, déplacé en tant que nœud (pas de manipulation de chaînes).
- **Polices** : mesurer les hauteurs **après** `await document.fonts.ready` (Tajawal `font-display:swap`).
- **Qualité PDF** : `company.pdfQuality` — `2` = Standard (~192 DPI, défaut), `3` = Qualité Pro (~288 DPI), `3.125` = Impression (300 DPI). Configurable dans "Mes Informations" > "Qualité du PDF"
- **Fond A4 natif** : l'en-tête/background n'est **plus** peint en `background-image` + html2canvas (perte de résolution/JPEG). Par défaut, le fond = **entit.png → JPEG 0.88** injecté nativement par page (`doc.image(...,210,297)`), le contenu est capturé en **PNG transparent** (`backgroundColor: null`). Si `company.headerActive` → l'image de marque de l'utilisateur (`resolveHeaderImage()`) remplace entit (ratio natif `210×210*h/w`, pas de fond entit). Flags d'override : `fb_pdf_bg` (`off`/`none` = désactivé, dataURI/URL = source, sinon défaut `/entit.png`), `fb_pdf_bg_mode` (`full`\|`header`), `fb_pdf_bg_fmt` (`png` natif \| `jpeg` réencodé 0.88).
- **Moteur par défaut = PDFKit, jsPDF = fallback** : `getPdfEngine()` → `pdfkit` sauf `localStorage.fb_pdf_engine === 'jspdf'` (opt-out). `renderPagesToPdf()` dispatche vers `js/pdfkit-engine.js` (helpers partagés `buildPdfHtml`/`buildPages`/`prepareTextElements`/`resolveHeaderImage`) en try/catch → **fallback jsPDF automatique** en cas d'échec bundle/rendu. Bundle `assets/lib/pdfkit.standalone.js` (0.19.1) lazy + `entit.png` **precached** (`facturation-v7`) pour l'offline. Ne pas supprimer jsPDF. Cf. `docs/audit/PDFKIT_ENGINE_INTEGRATION.md`.
- **Dépendances CDN lazy (Groupe C)** : html2canvas/jsPDF ne **sont plus** dans `app.html` — seuls `js/pdf-dependencies.js` (`ensureHtml2Canvas`/`ensureJsPdf`, promesses partagées + SRI `sha384-…` + retry) les injectent à la 1re génération. Chaque branche du pipeline doit `await` le(s) `ensure*()` nécessaires avant usage : `pdfkit-engine.js` (après `ensurePdfKit`) → html2canvas seulement ; `pdf.js` branche jsPDF → `Promise.all([ensureJsPdf(), ensureHtml2Canvas()])`. Ne pas ré-ajouter de `<script>` CDN au boot, ne pas bypasser `ensure*()`. Cf. `docs/audit/PDF_LAZY_DEPS.md`.
- **Métriques moteur** : `window.__pdfkitEngineMetrics` (steps bgResolve/bgEmbed/capture/embed/overlay/output, pages, sizeBytes, bg `{src,mode,fmt,width,height}`) — ne pas retirer sans adapter `tests/pdf/pdfkit-bg-experiment.spec.ts`.
- **Images par page attendues** : sans en-tête perso = **2** (fond natif + contenu PNG transparent) ; avec en-tête perso = **2** (en-tête + contenu) ; jsPDF = **1** (contenu JPEG 0.95) sans en-tête.
- **Mode BL** : `showTotalsDefault: true`
- **Mode exonéré** : `getRegimeConfig('exoneree')` → pas de HT ni TVA
- **`#pdf-stage`** : positionné à `left:-99999px` (LTR) ou `right:-99999px` (RTL)

### Storage
- **localStorage = source de vérité**, IndexedDB = backup. Ne pas inverser
- **Clés** : `fb_company`, `fb_history`, `fb_clients`, `fb_lang`, `fb_theme`, `fb_pdf_engine` (opt-out jsPDF)
- **`fb_company.pdfQuality`** : `2` (défaut), `3` ou `3.125` — résolution d'export PDF (192/288/300 DPI)
- **OPFS** : `facturation/pdfs/` et `facturation/header.png`
- **Mutex historique** : `withHistoryLock()` sérialise les écritures — ne pas contourner
- **Architecture history (Groupe D3.2)** : `js/history.js` = **noyau eager** (état édition `set/get/clearEditingDocId`, `withHistoryLock` exporté, `saveToHistory`, `migrateHistoryHeader`) ; **`history-view.js`** (renderHistory, delete) et **`history-actions.js`** (reprint/duplicate/convert) = **lazy `import()`**, precachés SW (`facturation-v7`). Les actions se chargent au **1er déclencheur** (UNIQUEMENT), pas à l'ouverture de la vue. `pdf.js`/`navigation.js`/`main.js` importent le **noyau** seulement ; `renderHistory()` est appelé via `import('./history-view.js')`, les handlers d'action via `getHistoryView()`/`getHistoryActions()` (promesses mises en cache). Ne pas re-fusionner avec le noyau, ne pas ajouter d'import statique de history-view/actions, ne pas re-rendre à l'ouverture. Cf. `docs/audit/HISTORY_ARCHITECTURE_AUDIT.md`.
- **Architecture company modal (Phase E2)** : `js/brand-logo.js` = **eager boot** (~250 o) — `updateBrandLogo()` est requis par `main.js` ET appelé par `saveCompanyForm` ; **`company-modal.js` + `storage-quota.js` = lazy `import()`** au **1er déclencheur** via le cache de promesse `getCompanyModal()` dans `main.js` (7 points de wiring : open, save, close, toggleTvaRate, syncColor*FromHex ×2, onHeaderFileChange). Garde anti-ré-entrance dans `openCompanyModal()` (overlay déjà `.open` → return). Les 3 modules sont **precachés** SW (`facturation-v7`). Ne pas remplacer par un import statique de company-modal, ne pas dupliquer `updateBrandLogo`, ne pas déplacer le cache de promesse hors de `main.js`. Cf. `docs/audit/COMPANY_MODAL_LAZY_LOADING.md`.

### i18n / RTL
- **`letter-spacing`** : supprimé en RTL (arabe) — `[dir="rtl"] .pdf-title { letter-spacing: normal }`
- **Direction** : `document.documentElement.dir` = `rtl` pour arabe, `ltr` sinon
- **Chargement (Groupe D)** : seule la **langue active** est chargée au boot (`js/i18n.js`), l'autre à la demande au 1er switch (`addResourceBundle` avant `changeLanguage`). Le `?v=Date.now()` (cache-busting) reste, avec **repli sur le chemin sans query** → servé par le precache SW (`facturation-v7`) → offline conservé et amélioré. Ne pas re-charger les deux locales au boot.

### CSS / Motion / A11y
- **Tokens accessibility (F2)** : `--muted-2`/`--accent`/`--accent-hover` sont **distincts par thème** (sombre `#8494ac`/`#5b5ae0`/`#4a49d0`, clair `#5c6d84`/`#5b5ae0`/`#4a49d0`) — AA 4,5:1 vérifié par `tests/audit/accessibility-f2.spec.ts`. Ne pas revenir à un token partagé, ne pas baisser les contrastes en dessous du seuil ni retirer la vérif de contraste.
- **Touch targets (F2)** : `.icon-btn` 36×36, `.col-actions` 40, `.hist-pagination button` 36/32 (mobile), `.admin-actions .btn` `min-height:34`. Compromis compact vs 44 px documenté — toute diminution casse `tests/audit/accessibility-f2.spec.ts`.
- **Hamburgers ARIA (F2)** : ouvrir/fermer `#appNav`/`#adminNav` **uniquement** via `setMenuOpen()` (`main.js`) / `setAdminMenuOpen()` (`admin.js`) qui synchronisent classe + `aria-expanded` ; ne pas modifier `aria-controls` (`appNav`/`adminNav`) ni retirer la fermeture Escape (admin = composé `closeAllModals()+setAdminMenuOpen(false)` — garder `closeAllModals` intact).
- **Labels i18n mono-source (F2)** : ne jamais remettre d'`aria-label` statique en dur là où un `data-i18n-aria-label` existe (`applyTranslations` l'applique à l'init + `setLang`).
- **Design tokens F3 (échelle)** : **31 tokens** définis dans `:root` (`styles.css`, l.47-55) — 12 `--space-*` (4→48 px), 10 `--fs-*` (11→20 px), `--radius-sm/md/pill` (6/8/20 px), `--shadow-lg:0 8px 24px rgba(0,0,0,.3)`, `--z-base/content/nav/modal/toast` (0/1/100/110/9999) ; s'ajoutent aux tokens existants `--radius:10px`/`--radius-lg:14px` et aux tokens F2/F1 (ne pas fusionner). Règles : toute **valeur répétée** doit utiliser un token (valeur du token = valeur de l'existant) ; une occurrence unique reste littérale ; **ne pas supprimer/renommer** de token sans relancer `tests/audit/design-tokens-f3.spec.ts` ; **zone PDF `styles.css` (~l.484-521) et `.pdf-*` de `rtl.css` non tokenisables** (valeurs `mm`/px spécifiques, phase PDF stabilisée) ; `!important` 11 inchangés (refactor = F4) ; hack autofill inchangé.
- **Tokens motion (F1)** : `--dur-micro/.12s`, `--dur-fast/.15s`, `--dur-normal/.2s`, `--dur-slow/.25s`, `--dur-slower/.3s`, `--dur-spin/.6s`, `--ease-out:cubic-bezier(0.4,0,0.2,1)` définis dans `:root` (`styles.css`) — valeurs exactes de l'existant, utilisables partout. **Ne pas créer d'autres tokens d'échelle en F1** (c'est F3), ne pas réintroduire de durées littérales pour du motion dans les feuilles CSS.
- **`prefers-reduced-motion`** : bloc global unique en fin de `styles.css` (app+landing+admin) — ne **jamais** cacher du contenu (pas de `display:none`/`opacity:0`), les spinners deviennent statiques (frame finale), le hack autofill (5000s) reste inchangé. Ne pas dupliquer ce bloc dans les autres feuilles, ne pas l'exempter sans revalidation `tests/audit/reduced-motion.spec.ts`.
- **Hack autofill** (`input:-webkit-autofill`, `transition:background-color 5000s ease-in-out 0s`, `styles.css`) : **à conserver littéral** (spécifique, hors tokens).
- **Spin buttons (F3.5)** : flèches d'incrément masquées via `input[type="number"]::-webkit-outer-spin-button,input[type="number"]::-webkit-inner-spin-button{-webkit-appearance:none;appearance:none;margin:0;}` + `input[type="number"]{-moz-appearance:textfield;}` (`styles.css`, l.158-160, zone « Browser-native elements theming »). Cible **uniquement** les inputs number — ne pas étendre à `[type=date]`/`[type=color]`/selects, ne pas modifier les autres surfaces natives (`appearance:none`+chevron des selects, `color-scheme`, `select option{}`, checkbox custom). Ne pas retirer les règles sans revalidation `tests/audit/native-ui-f3.spec.ts`.
- **Header admin défensif (F4)** : dans `admin.css` `@media (max-width:768px)`, `.app-header{flex-wrap:wrap;align-items:center}` (règle de base `wrap`) + `.admin-nav-mobile{display:flex;margin-left:auto}` — **ne jamais remettre `flex-wrap:nowrap`** (cause du scroll horizontal `#hamburgerToggle` ≤360 px, F4-D1). Le wrap absorbe n'importe quelle largeur de marque/RTL/zoom ; à ≥412 px une seule rangée (rendu identique). Garde : `tests/audit/responsive-f4.spec.ts` (zéro overflow page 320→768 admin/app/landing/RTL, computed wrap+margin). Les scroll-containers internes (`#histTableWrap`, `.admin-table-wrap` via `overflow-x:auto`) sont voulus — seul l'overflow **de page** (`document.scrollWidth`) est interdit.
- **Miroir icônes SVG RTL (F5)** : en RTL les glyphes SVG **ne sont pas mirorés par bidi** (seuls les caractères texte le sont — MDN/W3C/UAX#9). Ne pas changer le dessin des icônes dans `js/icons.js` pour RTL : le miroir est géré **CSS uniquement** dans `css/rtl.css` (l.118-129) par `[dir="rtl"] .hist-page-first/:prev/:next/:last svg` et `[dir="rtl"] .hist-action-btn[data-action="convert"] svg { transform:scaleX(-1) }`. Gardes : jamais élargir ces règles à LTR (scopées `[dir="rtl"]`), ne pas ajouter `!important`, ne pas retirer sans revalidation `tests/audit/rtl-f5.spec.ts` (computed transform RTL/LTR + ordre + zéro overflow 320/428/768).
- **Inputs de ligne (F6-H1)** : `aria-label` i18n (`js/lines.js:14-16`, clés `form.line_designation/line_price/line_qty`) sur désignation/prix/qte. Le **placeholder n'est pas un label** (transitoire) — ne pas retirer les `aria-label`, ne pas faire dépendre le nom accessible du placeholder. Garde : `tests/audit/accessibility-f6.spec.ts` (FR + AR).
- **Paramètres admin (F6-H2)** : les 8 `<label>` sont liés à leur champ par `for` (`modules/admin/settings.js`) — conserver l'appariement exact à chaque rendu (`sPlatformName`…`sValidationTime`). Garde : H2 (count=8, tous liés).
- **Tri historique clavier (F6-M1)** : `.hist-sortable` gardent leur handler clavier **Enter/Espace → cycleSort** (`js/history-view.js`) EN PLUS du clic, et `tabindex="0"` + `role="columnheader"` + `aria-sort`. Ne pas retirer le handler clavier ni le `tabindex`. Garde : M1 (aria-sort + première ligne après Enter).
- **Upload en-tête PDF (F6-M2)** : `#uploadBox` porte `role="button"`, `tabindex="0"`, `data-i18n-aria-label` (`app.html`) + keydown Enter/Espace → `headerFileInput.click()` (`js/company-modal.js`). L'input fichier reste `display:none`. Ne pas retirer `tabindex`/keydown ni rendre l'input visible. Garde : M2 (filechooser via Enter).
- **Erreurs landing (F6-M3)** : chaque `.field-error` de `landing.html` porte `role="alert"`, les inputs `aria-invalid` + `aria-describedby` (dispatcher dans `auth-modals.js` `showError`/`clearErrors`) ; **`#signupConfirmError` doit exister** (conteneur absent avant F6). Ne pas réintroduire d'input « confirmer » sans conteneur d'erreur, ne pas retirer `role=alert`.
- **Dialog confirm admin (F6-M4)** : `#confirmOverlay` (`admin/index.html`) a `aria-labelledby="confirmTitle"` + `aria-describedby="confirmMessage"` ; `confirmAction` (`modules/shared/ui.js`) place le focus dans le dialog, piège Tab et restitue le focus au déclencheur à la fermeture (Escape/Cancel/backdrop). Garder l'Escape admin composé intact (`closeAllModals` + `setAdminMenuOpen(false)`).
- **Contrastes F6 (M5/M6)** : `--footer-link:#6ea8fe` en sombre (7,75:1 sur `--bg`) / `var(--accent-2)` en clair, utilisé par `.app-footer a` ; `--success:#15803d` et `--warning:#a16207` **distincts en clair** (≥4,5:1 sur `--panel`), sombre inchangé (`#22c55e`/`#eab308`). **Ne pas revenir à des tokens partagés** ni descendre sous 4.5:1 (garde : M5/M6 = contrastes ≥ 4.5 mesurés éléments/tokens réels).
- **Focus modales landing (F6-M7)** : `auth-modals.js` capture le déclencheur (`modalsPrevFocus`, au 1er affichage seulement) et le re-focalise à la fermeture (Escape/backdrop/close). Ne pas retirer la capture ni le restore dans `hideAllModals`. Garde : M7 (activeElement = déclencheur après Escape).

## Règle de maintenance

Toute correction, tout audit, toute nouvelle information sur l'état du projet doit **mettre à jour CE fichier directement**, pas créer un nouveau fichier .md à la racine. Les rapports détaillés ponctuels vont dans `docs/audit/`. Les archives historiques vont dans `docs/archive/`.

Si un fichier devient obsolète (ex: test count ou score périmé), le déplacer dans `docs/archive/` plutôt que de le laisser dans `docs/audit/` où il pourrait être confondu avec l'état actuel.
